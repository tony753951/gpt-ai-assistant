# 權證分點大戶搜尋：接上真實資料

頁面開啟時會先讀取資料檔，讀不到才改用內建的模擬資料。頁面底部那行小字會寫出目前用的是哪一種。

## 三種提供資料的方式

1. **靜態檔（最簡單）：** 把資料存成 `public/warrant/data.json`，重新整理 `/warrant/` 就會讀到。
2. **指定網址：** 在網址加上 `?data=`，例如 `/warrant/?data=/api/warrant-data` 或 `/warrant/?data=https://example.com/data.json`。如果是別的網域，對方需要開放 CORS。
3. **自己寫 API：** 在 `api/index.js` 加一個路由回傳下面的 JSON，再用第 2 種方式指向它。

想先試試看，可以複製範例檔：

```bash
cp public/warrant/data.example.json public/warrant/data.json
npm start   # 然後開 http://localhost:<APP_PORT>/warrant/
```

## JSON 格式

```jsonc
{
  "source": "資料來源說明（選填，會顯示在頁面底部）",
  "latest": "2026-11-10",                       // 最新資料日（選填，預設為 calendar 最後一天）
  "calendar": ["2026-06-01", "2026-06-02", ...], // 交易日，YYYY-MM-DD
  "stocks": [
    { "code": "2330", "name": "台積電" }          // 權證的標的
  ],
  "brokers": [
    { "code": "9268", "name": "凱基-台北" },
    { "code": "9600", "name": "富邦總公司", "hq": true } // hq 選填；沒填時，名稱含「總公司／總行」就視為總行
  ],
  "bars": {                                      // 標的的日K，依日期對應
    "2330": { "2026-11-10": [開, 高, 低, 收, 成交量張數] }
  },
  "flows": [                                     // 分點在該標的「所有權證」的每日買賣超合計
    {
      "stock": "2330",
      "broker": "9268",
      "type": "call",                            // "call" 認購 / "put" 認售
      "days": { "2026-11-10": 425.3 }            // 單位：萬元，賣超為負數，沒交易的日子不用列
    }
  ]
}
```

注意事項：

- **金額單位是萬元。** 買賣超金額 = 成交股數 × 成交價 ÷ 10,000，同一分點、同一標的的所有認購（或認售）權證要加總成一筆。
- **缺少日K的日子：** 頁面會用前一天的收盤價補一根平盤K棒。
- **均線和布林通道** 是頁面自己用收盤價算的，不需要提供。
- **推估損益是粗估：** 算法是每日買賣超 × 標的漲跌幅 × 4 倍槓桿（程式裡的 `LEV`）。要算得準，需要權證本身的價格。

## 從證交所買賣日報表 CSV 轉換

`scripts/warrant/bsr-to-data.js` 可以把「買賣日報表查詢」下載的 CSV 轉成 `data.json`。

1. **把 CSV 依交易日放進資料夾：** CSV 本身沒有日期，所以日期要寫在資料夾或檔名裡。
   ```
   data/raw/2026-11-10/030001.csv
   data/raw/2026-11-10/030002.csv
   data/raw/2026-11-11/030001.csv
   ```
2. **準備權證對照表 `data/warrants.csv`：** 頁面要知道每檔權證的標的，以及是認購還是認售。
   ```
   權證代號,標的代號,標的名稱,類型
   030001,2330,台積電,認購
   030002,2330,台積電,認售
   ```
3. **（建議）準備標的日K `data/bars.csv`：**
   ```
   代號,日期,開,高,低,收,成交量
   2330,2026-11-10,1440,1455,1435,1450,38000
   ```
4. **執行：**
   ```bash
   node scripts/warrant/bsr-to-data.js --in data/raw --map data/warrants.csv --bars data/bars.csv
   ```

計算方式和行為：

- **金額怎麼算：** 每個分點的淨買超 = Σ（價格 × 買進股數）− Σ（價格 × 賣出股數），換算成萬元。同一標的、同一類型的權證會加總。
- **可以每天累加：** 輸出檔已存在時，只覆蓋這次處理到的日期，其他日期保留。
- **對照表沒列到的代號：** 會被略過，並列在警告訊息裡。
- **缺少日K時：** 如果資料夾裡剛好有標的本身的買賣日報表，會用當天的成交價區間暫代，開盤和收盤都填均價，所以K線不準。正式使用請提供 `--bars`。
- **總公司判斷是近似：** 分點代號末碼為 0 的視為總公司（例如 1020 合庫、9800 元大）。

## 資料從哪裡來

頁面只負責顯示，資料要另外抓下來整理成上面的格式。常見來源：

- **證交所「買賣日報表查詢」（上市）、櫃買中心（上櫃）：** 可查每檔權證的分點進出。需要逐檔、逐日查詢，而且有驗證碼。
- **付費資料服務：** 例如 FinMind、CMoney 等。各家的分點資料欄位和授權條款不同，使用前請先確認。

整理流程大致是：

1. 抓下每檔權證每天各分點的買進金額和賣出金額。
2. 用權證代號對照出它的標的和認購／認售類型。
3. 依「標的 + 分點 + 類型 + 日期」加總淨買超，換算成萬元。
4. 另外抓標的的日K。
5. 輸出成 `data.json`。

建議用排程每天收盤後重新產生一次。
